## 1. What is Tokenization? (How Words Become Tokens)

Computers don’t understand words, alphabets, or sentences—they only understand numbers. 

Before an LLM can understand your prompt, it has to convert your text into numbers. This conversion pipeline is called **Tokenization**.

```
┌─────────────────┐       ┌────────────────────────┐       ┌─────────────────────────┐
│   Raw Prompt    │  ──►  │    Token Chunks        │  ──►  │   Token IDs (Numbers)   │
│  "Learning AI!" │       │ ["Learn", "ing", " AI", "!"]│       │   [14820, 278, 9552, 0] │
└─────────────────┘       └────────────────────────┘       └─────────────────────────┘
                                  (Tokenizer)                    (Fed into the LLM)
```

### Are Tokens Just Words?
Not quite! A token can be:
- A full short word (e.g., `"dog"`, `"is"`, `"cat"`)
- Part of a longer word (e.g., `"un" + "believ" + "able"`)
- Punctuation marks, emojis, or spaces (e.g., `","`, `" 🚀"`)

### A Helpful Rule of Thumb
In English:
> **1 token ≈ 4 characters or 0.75 words**  
> **100 tokens ≈ 75 words**

Different languages and scripts consume tokens differently. English is very compact, while non-Latin scripts (like Hindi, Marathi, Arabic) might require 2 to 3 tokens for a single character because of how token vocabulary works!

## 2. Token Anatomy: Prompt vs. Completion vs. Total

Whenever you make a call to an LLM provider (like Groq or OpenAI), your response includes a `usage` breakdown:

```python
usage = response.usage
print(usage.prompt_tokens)      # Tokens sent IN (Your prompt + System prompt)
print(usage.completion_tokens)  # Tokens generated OUT (Model's answer)
print(usage.total_tokens)       # Sum of both (Your wallet's total bill)
```

| Token Type | What It Means | Why It Matters |
| :--- | :--- | :--- |
| **`prompt_tokens`** (Input) | Everything you sent to the model (user prompt + system message + history). | Usually cheaper per token, but can explode if your chat history is huge. |
| **`completion_tokens`** (Output) | The words generated by the model in response. | Usually more expensive to generate, and takes more computation time. |
| **`total_tokens`** | `prompt_tokens + completion_tokens` | This determines your final usage and cost for the request. |

## 3. Controlling the Tap: The `max_tokens` Parameter

By default, an LLM might keep talking until it thinks it’s finished (which could be hundreds or thousands of tokens). 

If you're building a production app or running tests, allowing endless generation will:
1. **Slow down response time** (latency increases with every token generated).
2. **Burn your API credits** faster than you expect.

Enter **`max_tokens`**.

`max_tokens` sets a strict upper bound on how many tokens the model is allowed to generate in its output (`completion_tokens`).

```python
response = client.chat.completions.create(
    model=model,
    messages=messages,
    max_tokens=50  # Hard stop after 50 output tokens!
)
```

---

## 4. Why Did the AI Stop? Decoding `finish_reason`

When an LLM stops generating text, it always tells you **why**. This is recorded in `response.choices[0].finish_reason`.

There are two common finish reasons you will see every day:

1. **`"stop"`**: The model naturally reached the end of its thought or hit an end-of-sequence token. Everything went smoothly!
2. **`"length"`**: The model had more to say, but you stopped it in its tracks because it hit your `max_tokens` ceiling!

### My Experiment from Today
In my Python script, I tested 3 prompts with `max_tokens=50`:

```text
Prompt 1: "hi"
-> Output tokens: 39 | Finish Reason: stop

Prompt 2: "What is machine learning in detail"
-> Output tokens: 50 | Finish Reason: length

Prompt 3: "Write essay on Indian constetuetion 100 words"
-> Output tokens: 50 | Finish Reason: length
```

Notice how `"hi"` completed naturally with `"stop"` using only 39 tokens. But both the Machine Learning prompt and the Essay prompt hit the 50-token barrier and were cut off with `"length"`!

## 5. Hands-On Code: Putting It All Together

Here is the clean, working Python script we built to observe tokenization and finish reasons in action:

```python
import os
from dotenv import load_dotenv
from groq import Groq

# 1. Load API Key
load_dotenv()
my_api_key = os.getenv("GROQ_API_KEY")
if not my_api_key:
    raise ValueError("API key missing! Check your .env file.")

# 2. Initialize Groq Client
client = Groq(api_key=my_api_key)
model = "openai/gpt-oss-120b"

# 3. Test prompts of varying lengths
prompts = [
    "hi",
    "What is machine learning in detail",
    "Write essay on Indian constitution in 100 words"
]

# 4. Iterate and inspect token usage
for prompt in prompts:
    message = {
        "role": "user",
        "content": prompt,
    }
    messages = [message]

    # Cap output at 50 tokens
    response = client.chat.completions.create(
        model=model,
        messages=messages,
        max_tokens=50
    )

    usage = response.usage
    finish_reason = response.choices[0].finish_reason

    print(f"Prompt: '{prompt}'")
    print(f"  • Prompt Tokens:     {usage.prompt_tokens}")
    print(f"  • Completion Tokens: {usage.completion_tokens}")
    print(f"  • Total Tokens:      {usage.total_tokens}")
    print(f"  • Finish Reason:     {finish_reason}\n")
```

## Key Takeaways from Day 4

1. **Tokens $\neq$ Words**: Think of tokens as word pieces. Always remember that 1 token is around 0.75 English words.
2. **Every Token Has a Price**: Both input tokens (`prompt_tokens`) and output tokens (`completion_tokens`) count towards your usage and quota.
3. **Guard Your Limits**: Use `max_tokens` to keep your LLM focused, fast, and within budget.
4. **Inspect the `finish_reason`**: If your app's user reports that an answer felt incomplete, check if `finish_reason == "length"`—you might just need to increase `max_tokens`!
